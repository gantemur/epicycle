# Scientific workspace architecture

Phase 4A established pure TypeScript state and capability contracts. Phase 4B mounts those contracts in a managed browser workspace. `app.ts` is now only an entry point; `workspace-app.ts` owns one live controller and one animation loop. The former Single/Compare `state.ts` controller has been retired. Phase 4B remains on its development branch for scientific and visual review before merging or deployment.

## Three boundaries

- **Clock:** `WorkspaceState.clock.ut1Jd` is the one authoritative, assumed UT1 astronomical Julian Day. Playing, speed, and direction also belong to this one clock. The live animation loop calls `tickClock`; no display owns a clock. `jumpToToday` takes an explicit UTC millisecond value through the existing UTC-to-assumed-UT1 boundary; the UI labels that approximation. Historical example jumps and steps set this same instant.
- **Historical model:** Versioned JSON parameter records remain authoritative. `model-registry.ts` declares each implemented model's body, source identity, source and validation status, dependencies, supported observables and their native frame labels, geometric view centres, and explicit policy domains. Evaluators use `modelDaysAtUt1` to convert the shared instant to the Ptolemaic Alexandria local day or the Copernican Frauenburg local day. Alexandria 30° E remains provisional; Frauenburg 19°40′ E is documented. Neither local day is a modern TT timestamp.
- **Display:** A serializable, version 1 discriminated union has `geometry` and `time-series` configurations. A geometry panel selects one body/model/policy/centre plus trail, circles, construction lines and annotations. A plot selects its own trace list, window, longitude wrapping, axis labels, optional follow flag, frame declaration and analysis mode. `startUt1` and `endUt1` alone define its window; pan and zoom transform those endpoints rather than storing competing offsets or scale. Follow time shifts the window only when the marker leaves its central 60%, preserving the span. The plot's window never changes the current clock instant; its marker reads `clock.ut1Jd` directly. The plot cache key excludes clock time and language, so moving a marker alone does not resample unchanged curves.

The live UI derives Ptolemaic and Copernican arguments from the shared UT1 instant through `modelDaysAtUt1`. The original fixture-derived Nabonassar example remains in `historical-examples.ts`; `ptolemyDayToAssumedUt1` is the explicit inverse of the provisional Alexandria conversion, tested with the original day convention. Manual Frauenburg Julian dates, the Egyptian day count, 1473 and 1512 jumps, Today, and stepping all change the same clock.

## Validation and availability

`validateDisplay` checks mathematical model/body, observable, view centre, policy, plot settings, trace IDs, and frame conditions. Renderer availability is a separate registry field. Ptolemy has only an Earth-centred mathematical and rendered geometry capability; a physical true-Sun Ptolemaic view is unsupported. Copernicus has Earth and true-Sun-centred mathematical geometry, but only an Earth-centred renderer at present. A true-Sun configuration is mathematically valid and reports `renderer-unavailable` until its renderer and labels exist; it must not be offered as a working UI choice before then.

The source-limited Copernican `sn-local-uniform-1473-1523` policy uses the existing 1473–1523 guard. `sn-uniform-exploratory` is a separately selected continuation, never an automatic fallback. New longitude-comparison plots explicitly select the exploratory policy for Copernicus; geometry defaults remain source-limited. Changing a plot window never changes a trace policy. `displayAvailabilityAt` describes the current-time marker/readout, including a partial result when only some plot traces are available there. Independently, `traceCoverage` describes full, partial, or no coverage of the plot's historical window. A plot entirely within 1512 remains usable when the global clock is in 2026, even though a source-limited Copernican marker is unavailable. The sampler records unavailable dates as null values; the SVG renderer breaks curves at those gaps and suppresses unavailable current values. For an exploratory trace, exact guard-boundary instants are sampled and the path stays mathematically continuous: solid within the project-chosen reference interval, dashed outside it. This guard is not an established accuracy interval, and neither stroke claims observational validation. The capability registry declares the exploratory reference interval, leaving room for later models to declare their own. A failed panel cannot stop the clock or other panels. The wider JD 1,200,000–3,000,000 boundary is numerical only, not a historical validity claim.

Plot `overlay` means displaying selected traces together, including future different bodies. Each trace's native frame is available through its model registry entry and `nativeFrameForTrace`; a native overlay must label these frames separately and must not treat unlike frames as aligned. `model-disagreement` draws one signed principal curve, `Δλ = angularDifference(λ_B, λ_A)`, in the evaluator's `[−180°, 180°)` convention. It requires two different models of the same body and observable, with a common native frame or an explicit **nominal historical tropical alignment**. The curve has its own symmetric degree scale and zero line; branch jumps and unavailable source dates split the line. If either source is an exploratory Copernican continuation, the derived curve is dashed outside its declared reference interval. That alignment is not a calibrated modern frame, particularly over century-scale windows. Cross-body angular separation is a different mathematical operation; observational error requires a calibrated reference and matching metadata. Neither is implemented or silently inferred from an overlay. The reconstructed Copernican Mars apogee remains tied to its selected policy and restricted source domain.

## Panel and preset behavior

`workspace-state.ts` supplies pure add, remove, collapse, reorder, replace-settings, window-transform, clock, and preset operations. Added and updated panels copy their nested trail, window, trace, and analysis settings, including when a preset draft is reused. IDs are monotonic (`panel-1`, etc.) and stable through ordering/removal. Up to four panels are active, including collapsed ones; an empty workspace has an Add Display control. A plot allows up to four traces as a UI limit, not a limit on future historical models. The same model can appear in several panels with independent settings. `restoreWorkspace` validates version, configuration, panel IDs, and the next-ID counter, copies the panels, and forces `playing: false`; invalid saved data is rejected. It does not read browser storage, and persistence is not enabled yet.

Presets are Explore one model, Compare longitudes, Desktop explore, and Detailed comparison. The suggested desktop start is a longitude plot plus one Ptolemaic construction; the suggested phone start is the plot alone. Suggestions apply only when creating a new workspace. Resizing an existing workspace changes presentation only and must not call `applyWorkspacePreset` or discard panels.

## Phase 4B rendering and remaining boundaries

`workspace-app.ts` mounts stable panel shells. `workspace-geometry-view.ts` and `workspace-plot-view.ts` replace static settings on configuration or language changes, while their dynamic paths update SVG geometry, the time marker, and numerical readouts. Plot boundaries accept a Julian year, date, or full local date-time; a year alone means January 1 at 00:00, so 1500–1600 is the 36,525-day interval between those instants and does not include the rest of 1600. The shared clock retains its strict full date-time input. The plot sampler in `workspace-plot.ts` uses at most three historical days between samples. A trace-policy change reuses unchanged trace evaluations on the same time grid; ordinary clock ticks reuse the whole sampled plot. The SVG renderer omits subpixel path vertices while keeping all evaluated samples and exact segment endpoints; this also makes long dashed paths visible in Safari. The previous comparison sampler retains its 50-year range guard; the managed workspace permits a 100-year custom window so the requested 1500–1600 source-coverage example can be shown. This is a display-window limit, not a new historical claim. A 100-year two-trace sample completes in the frontend regression test. The browser's ordinary selectors list only implemented Mars models and Earth-centred geometry.

At phone width, the plot precedes the extended date controls; the single transport remains sticky while examining the plot or a diagram. Presets are deliberate replacements and viewport changes never apply one automatically. Geometry tap-to-play is deferred: it needs deliberate tap-versus-scroll behavior on the stable diagram container and a separate browser interaction check. Drag-and-drop, true-Sun rendering, browser persistence, shareable layouts, modern calibration, and new observables also remain later work.

Future latitude, additional bodies, and historical variants add new sourced evaluators and capability entries, then the relevant display/evaluation support. A model ID in a panel refers to a registry record rather than copying parameters. A synthetic Saturn capability appears in unit tests solely to demonstrate validation rules; it is not an implemented astronomical model or UI choice. Future sky-path, numerical readout, and diagnostics display types can extend the union after their scientific and rendering contracts are defined.
